报警处理:

1、用户提币资产不足

    查mysql的fund库中hedge表,根据实际和curreny字段过滤,查看对冲阈值和对冲数量的差距
    若有敞口需要对冲,则在现货管理后台——对冲管理——对冲配置中心(管理员),
    页面中选择要对冲的币种,点击搜索,拉到最右边点击编辑,
    修改“对冲阈值”和“对冲阈值价值”,改为5-10U可以基本做到完全对冲

   确认需要划转资金
   在生产管理后台——资金划转管理——资金划转
   点击左侧“资金划转”,输入转出ID和转入ID,以及币种+数量
   转出ID一般是现货做市账户:11,12,13先转入17 只能用17转到196
   点击确定划转
   在右侧点击审核,再次确认转账操作内容

   有另一个解决办法,是将http://10.0.208.223:5000/ 现货管理后台——对冲配置中心(管理员)
   页面中选择要对冲的币种,点击搜索,拉到最右边点击编辑,
   修改“对冲阈值”变大 和“对冲阈值价值(USDT)”变大, 就不会报错了
   这就是为什么参数改小后,等对冲完成后,需要将数值再调回来。否则会一直报错


3、资金不足,需要操作借贷的操作
   
   在现货管理后台——对冲管理——杠杆借贷(币安)
   1、在左侧“杠杆借贷”第三行划转USDT(主——全),数量比需要借贷的金额多一些
   2、查右侧“查询币种详情”,选择要借贷的币种,查借贷金额是多少
   3、在左侧“杠杆借贷”第一行,填写要借贷的币种,要借贷的金额
   若失败会提示失败信息
   资产到账后,操作还币
   1、查右侧“查询币种详情”,选择要还的币种,数量比接入的数量要多
   2、在左侧“杠杆借贷”第二行,填写要还币的币种以及数量
   3、查右侧“查询币种详情”确认全部还币完成


4、排查现货当日盈亏异常的方法

    群名：现货 合约 盈利亏损
    ```
    【现货】

    当月盈亏:-1,321   订单盈亏:-1,325  
    累积盈亏:57,553   订单盈亏:59,317

    若当日盈亏异常,先排查是否有出入金的操作。若有,则对比金额是否一致
    若没有,则排查mysql的fund库中mongoorders表(这个表是内盘成交记录),查看逐笔对冲细节,是否滑点较大

    ```

    各个价格源有价差：
    1、看是否是偶然行情波动
    2、是否有些因为成交不活跃
    3、综合考虑是否去掉某些价格源

    2026-02-17 20:54:57.591194 spot_hedge 
    >>>>>>>>>gate 需要对冲 0.07203023911884864 XAUT  资金不够对冲，请联系资产 @TB147258
    但是资产反馈如下：
    我意思gate也没有资金 平台里也没有资金。0.072个不见了
    当有资金找不到的时候，如何排查？
    
    从mysql的fund库中mongoorders表查看所有内盘成交记录
    从mysql的fund库中hedge表查看所有对冲记录
    一般情况下，对冲不会出现问题
    需要单独查看mongoorders内盘成交记录中，按用户id筛选，查看每个用户的buy和sell情况
    是否出现buy少，但是sell多的情况
    筛选出这部分用户，让资产去查原因
    之前出现过的情况是：
    1、有手续费返还，所以会凭空多出一些资金，用户在内盘卖出，没有对应资产在外盘卖
    2、内盘空投奖励，情况同上
    
13、群名: 价格精度&深度监控
    【现货】买卖1价差低于1个价格价格精度,连续三次超过设置参数,请相关同事注意 (2min/次)
    【MOVE-USDT】：ask1:0.0224 bid1:0.0223 价差:0.0001
    说明买卖一价格中间没有价差
    理论上不需要处理,但有些交易对会频繁报警
    可能的解决办法是:
    1、调整价格精度,增加1位,让盘口有价差
    2、修改监控逻辑,在monitor项目的spot_acc_gear_depth.py文件的get_depth_price函数中
       把df2 = df[(df['price_reduce'] <= df['price_precision']) 修改为
       df2 = df[(df['price_reduce'] < df['price_precision']) 即使价格贴在一起也不会报警
    一般会用第一种办法
